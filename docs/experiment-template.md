# 实验记录模板（experiment template）

这份文档不是一篇总结，而是一个**可直接复制的模板**。  
以后你每做一轮新实验，建议都先复制这份模板，再填内容。

推荐命名方式：

```text
docs/experiments/YYYY-MM-DD-<topic>.md
```

如果你暂时还没单独建 `docs/experiments/` 目录，也可以先放在你当前最方便管理的位置，但格式尽量保持统一。

---

## 1. 为什么要用模板

不用模板时，最容易漏掉这几类信息：

- 这轮到底想验证什么
- 改了哪个文件
- 这轮有没有重编 / 重启 / 重新生成
- 测的样本 hash 是什么
- 证据文件放在哪
- 结论到底是“成功”“失败”还是“环境阻塞”

用了模板以后，回头看会清楚很多。

---

## 2. 复制用模板

下面就是建议直接复制的模板：

```md
# <实验标题>

## 日期
- YYYY-MM-DD

## 背景
- 这轮实验为什么要做
- 它接在前一轮哪条研究线上

## 目标
- 这轮想验证的具体问题

## 假设
- 如果 A 成立，会看到什么
- 如果 B 成立，会看到什么

## 变动范围
- 本轮是否改源码：是 / 否
- 改动层级：
  - direct_https Go 插件层 / beacon 层 / loader 层 / packer 层 / 文档层

## 涉及文件
- `path/to/file1`
- `path/to/file2`

## 本轮改动摘要
- 用一句话概括每个改动点

## 构建与生效动作
- 是否重编：是 / 否
- 是否同步 runtime：是 / 否
- 是否重启 runtime/teamserver：是 / 否
- 是否重新生成 payload：是 / 否
- 是否重新打包 container：是 / 否
- 是否重新替换 Windows 落地文件：是 / 否

## 样本/产物信息
- loader:
  - path:
  - sha256:
- payload/container:
  - path:
  - sha256:

## 测试环境
- Git branch:
- 本地 commit/tag:
- Windows 主机：
- C2 / API / listener：
- 启动方式：

## 执行步骤
1. ...
2. ...
3. ...

## 关键观察
- 观察 1：
- 观察 2：
- 观察 3：

## 关键证据
- `path/to/evidence1`
- `path/to/evidence2`
- `path/to/evidence3`

## 结果判定
- PASS / FAIL / BLOCKED / INCONCLUSIVE

## 结论
- 这轮实验实际说明了什么

## 未解决问题
- 还有什么没有解释清楚

## 下一步
- 下一轮最合理的动作是什么
```

---

## 3. 推荐你每轮至少填满的字段

如果赶时间，最少也尽量把下面这些写全：

- `目标`
- `涉及文件`
- `构建与生效动作`
- `样本/产物信息`
- `关键证据`
- `结果判定`
- `结论`
- `下一步`

这 8 项是最关键的。

---

## 4. 结果判定建议

为了让后面回看更快，建议尽量用固定词：

| 判定 | 什么时候用 |
|---|---|
| `PASS` | 实验目标达到，证据明确 |
| `FAIL` | 明确证明假设不成立或结果相反 |
| `BLOCKED` | 被环境问题卡住，例如网络、主机、依赖、权限 |
| `INCONCLUSIVE` | 有观察，但证据还不足以下结论 |

---

## 5. 和其他文档的关系

### 这份模板是“单轮实验记录”

它负责回答：

- 这一次具体做了什么

### `CHANGELOG.md` 是“阶段变更摘要”

它负责回答：

- 最近这个仓库整体多了什么

### `docs/decision-log.md` 是“长期决策记录”

它负责回答：

- 为什么长期策略要这样定

所以三者不要混用。

---

## 6. 最后的建议

以后每次开始实验前，先复制这份模板，再开始动手。  
这样你后面不管是自己回看、整理阶段总结，还是给老师汇报，都会轻松很多。
